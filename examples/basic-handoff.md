# 入门示例：把一个普通项目交给新对话

这是虚构的教学案例，文件内容、进度和对话回复均为示意，不是实际执行记录。阅读或复制示例不代表已经创建、接管或归档任何任务。

## 场景：图片整理小工具

旧对话正在帮你做一个图片整理工具。文档记录“导入入口已完成，导出还没做”，聊天刚停在“先支持 PNG 导出”。你希望新对话接着这个停点工作。

先看是否已有足够的当前文档。这个例子有三份：

```text
image-helper/
├── AGENTS.md
├── README.md
└── CURRENT_PROGRESS.md
```

**AGENTS.md：说明读什么、权限到哪里。**

```markdown
# 项目入口
先读 README.md 和 CURRENT_PROGRESS.md。
本次交接恢复期间只读，不修改文件、不运行项目、不提交或部署。
后续开发由用户另行授权；只使用虚构测试图片，不读取个人相册。
```

**README.md：说明项目做什么。**

```markdown
# 图片整理小工具
为选定图片加上标签并导出整理结果。
当前阶段是本地原型；真实图片与个人相册不属于本次交接范围。
```

**CURRENT_PROGRESS.md：保存当前停点。**

```markdown
# 当前进度
- 文档记录：导入入口已完成，导出尚未实现。
- 导入是否覆盖全部格式边界仍待验证；没有完整运行验收记录。
- 下一步：讨论最小导出范围，得到确认后再实现。
```

这些文件大致够用，所以选择“已落库快速路径”。无需为了交接把旧聊天全文复制一遍。如果文件彼此矛盾或缺少关键决定，先补核对，再判断是否需要另一条路径，不能硬套本例。

## 第一步：只准备交接，暂不创建新对话

在旧对话里说：

```text
使用 $codex-thread-handoff，先只准备交接。
核对这个项目的 AGENTS.md、README.md 和 CURRENT_PROGRESS.md，
只补文档没有记录的决定与讨论停点。
不要创建新任务、改名或归档，也不要修改文件、运行项目或操作 Git。
```

旧对话可以给出这样的短补充：

```markdown
# 交接补充（示意）
- 当前信源：AGENTS.md 是规则入口；README.md 定义用途；
  CURRENT_PROGRESS.md 记录当前进度；实现事实以后需核对相关源码。
- 文档未记录的决定：第一版先支持 PNG 导出，暂不讨论其他格式。
- 讨论停点：还没确定导出文件如何命名，也没有授权开始实现。
- 下一入口：先讨论最小导出范围。
- 边界：新对话恢复只读；导入运行结果未验证；不读取个人相册。
```

不要把这份补充称为新的实现证据。它记录的是旧对话里的决定；如果与当前文件冲突，必须说明冲突。

## 第二步：明确同意后，让新对话只读恢复

你决定要创建新对话时，再明确说：

```text
可以创建一个干净、非 Fork 的新任务用于交接验收，先只读恢复。
先核对实际工作目录以及三份当前文件能否读到，
再传入刚才的交接补充；旧对话保持可读，不改名、不归档。
按我明确选定的模型和思考强度调用；查不到设置或工具不支持时说明限制。
```

创建之前还要核对是否有与当前状态相关的未提交文件。有的话，应选能读到这些文件的工作区；不能假设新的 worktree 自带这些改动。没有创建工具时，返回恢复提示，由你手动新开对话，不宣称创建成功。

给新对话的恢复提示可以是：

```text
你是这个项目的接管候选，目前只读恢复，尚未正式接管。
先核对实际工作目录，然后读 AGENTS.md、README.md、CURRENT_PROGRESS.md，
再读明确传入的交接补充。若缺失、冲突或没有读取权限，指出具体缺口。
简短说明读了什么、文档中的当前进度、未验证事项、权限和下一停点。
不要修改文件、运行项目、读取个人相册、操作 Git 或归档任何对话。
```

新对话的一份合适回复可能是：

> 已核对工作目录并读到三份文件与交接补充。文档记录导入已完成，但没有完整运行验收；本轮也没有核对源码或运行项目，因此不确认实现及运行能力。导出尚未实现，旧对话补充的决定是先支持 PNG。下一步先讨论命名和最小导出范围，目前没有开发、Git 或部署授权。

这里重要的是分清“文档怎么记载”和“实际验证过什么”。如果它说“PNG 导出已经完成并验证”，就没有接对，应先纠正或补查，不能收口交接。

## 第三步：你确认接对了，再正式切换

你可以自然地问“下一步做什么”“现在是否可以写代码”，不需要固定题数或评分表。只有你确实确认恢复准确，才授权正式接管。

例如：

```text
恢复准确，可以正式接管。
将新任务改名为“图片整理小工具”，旧任务改为带日期的旧对话并归档，不删除。
允许在这个项目的现有进度文档里简短记录本次交接。
仍然不要开始开发、commit、push 或部署。
```

Agent 应回读并报告实际完成的任务操作；工具不可用或操作失败时明确说明。验收通过不代表新功能做完，也不会自动获得下一步开发权限。

交接到这里结束。随后是否实现导出、如何验证和是否提交，都由你另行决定。

## 什么情况下不要照着走

- 大部分信息还在聊天里：使用一份独立交接文档，见 [handoff-packet.md](../skill/codex-thread-handoff/references/handoff-packet.md)。
- 信源冲突、敏感权限、以前交接失败或要求严格验收：按 Skill 的严格路径处理，见 [完整演练](complete-walkthrough.md)。
- 只是继续同一个对话：不用为了使用本 Skill 强行创建新任务。
